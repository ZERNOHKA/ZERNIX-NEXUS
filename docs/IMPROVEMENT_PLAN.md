# План улучшения проекта

Этот документ фиксирует, что стоит улучшить в ZERNIX NEXUS, чтобы проект выглядел сильнее как портфолио и был ближе к уровню уверенного middle-разработчика.

## Текущее состояние

Проект уже выглядит как законченная desktop-утилита:

- есть графический интерфейс;
- есть разделение на `core/`, `ui/`, `docs/`, `assets/`;
- есть demo-режим для портфолио;
- есть лицензирование через внешний сервер;
- есть скриншоты и README;
- есть скрипты сборки;
- есть QA-чеклист и матрица действий.

Главная проблема сейчас не в идее проекта, а в поддерживаемости кода: часть файлов слишком крупная, а некоторые системные действия смешаны между собой.

## Приоритет 1: архитектура

### Разделить `core/tweaks.py`

Сейчас `core/tweaks.py` содержит слишком много ответственности: реестр, службы, CS2-конфиг, сеть, rollback, диагностика, power plan, cleanup и статус системы.

Лучше разбить на модули:

```text
core/
├── system_info.py
├── registry_backup.py
├── power.py
├── services.py
├── network.py
├── cs2.py
├── rollback.py
├── diagnostics.py
└── tweaks.py          # только фасад или совместимость
```

Польза:

- легче читать;
- проще тестировать;
- проще объяснять проект на собеседовании;
- меньше риска сломать unrelated-функции при правках.

### Продолжить разделение `main.py`

Переводы и модель действий уже вынесены в `app/`. В `main.py` пока остаются запуск, сборка страниц, обработчики, асинхронное выполнение и license overlay.

Лучше вынести:

```text
app/
├── application.py       # следующий этап
├── translations.py      # выполнено
├── actions.py           # выполнено
├── navigation.py
└── startup.py
```

Польза:

- `main.py` станет короткой точкой входа;
- UI станет понятнее;
- переводы можно редактировать отдельно.

## Приоритет 2: безопасное выполнение Windows-команд

Сейчас в проекте много вызовов `subprocess` и `shell=True`. Для Windows-утилиты это нормально, но для качества кода лучше сделать общий слой запуска команд.

Пример будущей структуры:

```python
CommandResult = dataclass(...)

def run_command(args: list[str], timeout: int = 30) -> CommandResult:
    ...
```

Что улучшить:

- единый timeout;
- единый лог ошибок;
- единая обработка `stdout/stderr`;
- меньше `shell=True`;
- безопаснее передавать аргументы.

## Приоритет 3: rollback и backup

Проект меняет чувствительные настройки Windows, поэтому самый сильный плюс для портфолио - надежный откат.

Что стоит добавить:

- единый список всех изменяемых ключей реестра;
- JSON backup со временем создания и версией приложения;
- проверку, что backup создан до агрессивного действия;
- экран “Что будет изменено” перед применением пресета;
- отчет после применения: что изменено, что пропущено, что требует перезагрузки.

## Приоритет 4: модель действий

Сейчас UI-строки и backend-функции связаны вручную через списки `system_rows`, `gaming_rows`, `preset_jobs`.

Лучше сделать декларативную модель:

```python
@dataclass
class AppAction:
    key: str
    title_key: str
    description_key: str
    handler: Callable[[], str]
    requires_admin: bool
    category: str
    rollback_note: str
```

Польза:

- одна структура управляет UI, логикой, документацией и audit matrix;
- меньше копипаста;
- проще добавлять новые действия.

## Приоритет 5: тесты

Для desktop Windows-утилиты не нужно тестировать все системные изменения на реальной машине. Но можно покрыть чистую логику:

- нормализация license key;
- HWID fallback;
- построение CS2 launch options;
- upsert строк в `autoexec.cfg`;
- mapping статусов dashboard;
- parsing ping/network diagnostic;
- формирование rollback payload.

Минимальный набор:

```text
tests/
├── test_licensing.py
├── test_cs2_config.py
├── test_status_mapping.py
└── test_actions_model.py
```

## Приоритет 6: визуал

Интерфейс уже выглядит цельно, но можно усилить:

- добавить light/dark theme toggle;
- сделать responsive layout вместо фиксированного размера окна;
- добавить экран “Activity history”;
- добавить бейджи: `Admin required`, `Reboot`, `Rollback available`;
- показать перед запуском пресета карточку “Будет изменено”;
- добавить toast-уведомления вместо части messagebox;
- сделать отдельный экран диагностики системы.

## Приоритет 7: документация

README уже подходит для портфолио. Следующие улучшения:

- добавить GIF или короткое видео запуска demo-режима;
- добавить раздел “Архитектурные решения”;
- добавить раздел “Почему нужен rollback”;
- добавить “Known limitations”;
- перевести `AUDIT_MATRIX.md` и `QA_MANUAL_CHECKLIST.md` на русский или сделать оба файла двуязычными.

## Что даст самый сильный эффект

Если делать не все, а только самое важное:

1. Разбить `core/tweaks.py`.
2. Продолжить декомпозицию `main.py` после вынесенных переводов.
3. Дополнить `AppAction` метаданными прав администратора и отката.
4. Расширить минимальные тесты чистой логики.
5. Улучшить rollback-отчет после применения пресетов.

После этих шагов проект будет восприниматься заметно сильнее: не просто “красивая программа”, а поддерживаемый продукт с архитектурой, безопасностью и понятной инженерной логикой.
